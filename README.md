# Legit — Obsidian

Интерфейс на [Obsidian](https://github.com/deividcomsono/Obsidian) с семью вкладками из референсов: **Aimbot, Combat, Character, ESP, Misc, Players, UI Settings**. Настройки Aim, ESP и Melee Aura сохранены и сгруппированы по назначению. UI поддерживает поиск, изменение размера окна, цвета, прозрачность, привязки клавиш и масштаб.

## Запуск

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/sinmirka/Legit/main/Legit.lua"))()
```

Один файл, одна HTTP-загрузка. Obsidian, Lucide и логика встроены в `Legit.lua`; дополнительных загрузок Lua при запуске нет. Drawing API и `getcustomasset` не нужны. Иконки и текстуры используют Roblox asset IDs.

Нужны `loadstring`, `getgenv` и файловые функции для профилей. ESP, Aimbot, Silent Aim, Melee и все изменения персонажа / освещения изначально выключены. Старый экземпляр при повторном запуске выгружается. Кнопки Dex и Remote Spy загружают внешние инструменты отдельно, только по нажатию.

В Aimbot по умолчанию проверка команды и исключение ForceField отключены: цели выбираются среди остальных живых игроков. Эти фильтры можно включить отдельно. У Melee собственные фильтры; ForceField изначально исключается.

## Управление

| Действие | По умолчанию |
| --- | --- |
| Открыть / закрыть меню | **RightShift** |
| Наведение | **Удерживать ПКМ**, после включения Enable aimbot |
| Изменить клавишу наведения | Aimbot → Aim key, затем нажать нужную клавишу / кнопку мыши |
| Очистить привязку | Выбрать Aim key и нажать **Backspace** |
| Изменить клавишу меню / масштаб | UI Settings → Menu key / UI scale |
| Выгрузить UI и функции Legit | **END** или UI Settings → Unload |

Наведение работает при открытом меню, когда курсор находится вне панели. Клик по настройкам, ввод текста и перетаскивание приостанавливают наведение. Можно отдельно включить Pause while menu is open.

Ползунки поддерживают числовой ввод через правую кнопку мыши. Цвет, HEX / RGB и прозрачность задаются в color picker Obsidian. Dropdown открывает список с поиском. **UI Settings → Show aim status** показывает состояние наведения; **Toggle status watermark** включает перетаскиваемую строку состояния.

### Отладочные логи

В **UI Settings → Debugging / Combat diagnostics** нажми **Start melee capture** или **Start silent capture**. Это включает только сбор диагностики, без включения атак. Затем включи нужную функцию, закрой меню и воспроизведи проблему. **Save debug report** сохраняет `Legit/Universal/logs/latest.txt` в файловой workspace executor, **Copy debug report** копирует отчёт. **Stop debug capture** останавливает запись с сохранением накопленного отчёта, **Clear debug log** очищает его и счётчики.

Журнал хранит последние 400 записей в памяти. В нём доступны API executor, текущие настройки, причина паузы, распознанное оружие, причины исключения целей, попытки Activate / события Activated, количество наблюдаемых и перенаправленных Raycast и причины пропуска лучей. С подробной трассировкой записываются путь вызывающего скрипта и клиентский результат луча. Частые записи ограничены по частоте. Счётчики исключения целей считают оценки на Heartbeat, а не уникальных игроков.

По умолчанию логирование и вывод в консоль выключены. Ничего автоматически не отправляется в сеть и не пишется в файлы. Ошибки диагностики hook пропускают вызов исходному методу; ошибки и возвращаемые значения самой игры сохраняются. Клиентское попадание не доказывает серверный урон. Без событий Raycast в отчёте нельзя заключать, что игра вообще не использует Raycast: прямые `.Raycast(...)` вызовы этим hook не видны.

Для проверки окружения без полной загрузки UI есть `tools/probe_runtime.lua`: он сохраняет `Legit-runtime-probe.txt` в workspace executor, без установки hooks и вызовов игровых remotes. В живой проверке Xeno 14 ноября 2026 года `hookmetamethod` и `getnamecallmethod` оказались `nil`; текущая Raycast Aura требует эти API и в таком окружении недоступна.

### Что отложено

По референсам сохранены вкладки и близкие группы настроек. Отложены Triggerbot, recoil / wallbang / auto-block, отдельные Rage Melee / Hit Reg, Ghost Hunt, stamina / no fall / ragdoll, удаление игровых препятствий, loot / dealer / infection ESP, auto pickup / lockpick / staff detector и hitsounds. Fly и анимационные инструменты тоже отложены до отдельной реализации и проверки в игре.

### Универсальные функции

Настройки персонажа применяются к текущему Humanoid и подхватывают респавн. Noclip запоминает исходный CanCollide каждой части. При выключении или выгрузке изменённые значения восстанавливаются, если ими всё ещё управляет Legit; более новые изменения игры не перезаписываются. Эти клиентские настройки не обходят серверные ограничения движения.

World меняет локальное освещение. Bloom и ColorCorrection создают собственные эффекты и удаляют только их. Для Atmosphere используется имеющийся объект с восстановлением свойств, либо создаётся временный объект. Прозрачность цветов относится к ESP/FOV; у свойств Lighting нет opacity.

В Players **Friend** исключает игрока из Aim, Silent и Melee, сохраняя его в ESP. **Enemy** предпочитается среди целей, прошедших фильтры; Sticky у Camera Aim продолжает удерживать текущую допустимую цель. Приоритеты действуют до выхода игрока / выгрузки, в профиль не сохраняются. Наблюдение отслеживает респавн выбранного игрока и возвращает камеру при остановке, его выходе или выгрузке.

Dex / SimpleSpy запускаются как отдельные инструменты и закрываются через собственные интерфейсы. Они могут загружать свои зависимости и требовать дополнительные API executor. Legit обрабатывает ошибку загрузки / компиляции / запуска и допускает повторную попытку; повторное успешное нажатие в одном экземпляре Legit не запускает вторую копию. Их работа в клиенте здесь не проверялась.

### Цвета и прозрачность

- **Opacity**: `0` — невидимо, `1` — непрозрачно.
- Итоговая видимость Chams учитывает Global opacity, Fill opacity и прозрачность выбранного цвета. Fade и Pulse дополнительно изменяют её.
- Приоритет цвета персонажа от высшего к низшему: **текущая цель → rainbow → цвет команды → видимый / скрытый → базовый цвет**. Выключи переопределения, если хочешь видеть базовые Fill / Outline.
- Для независимого цвета рамки выключи **Match character color**. Прозрачность текста и его обводки регулируются отдельно.
- **Character outline** — силуэт Highlight со стандартной толщиной Roblox. Настраиваемая толщина относится к 2D-рамкам, скелету, линиям и FOV.

### Выбор цели

FOV — радиус в пикселях вокруг центра экрана. Deadzone останавливает поворот камеры, когда цель достаточно близко к центру; выбранная цель при этом сохраняется. Большая Aim speed означает более быстрое наведение. Instant убирает плавность.

Для R6 выбор UpperTorso / LowerTorso использует Torso, а UpperArm / UpperLeg — соответствующие Arm / Leg. Другие отсутствующие части тела исключают цель. Смещение XYZ задаётся в мировых координатах; prediction добавляет скорость HumanoidRootPart × Prediction time. Наведение поворачивает камеру; стрельба и регистрация попаданий остаются механиками игры.

Check walls проверяет путь до выбранной части тела. ESP проверяет видимость до головы; для Highlight дополнительно применяется режим Occluded. Для 2D-элементов проверка головы определяет отображение всего оверлея. Прозрачное стекло с CanQuery может считаться препятствием; вода игнорируется.

### Если нет наведения

Включи Aimbot → Enable aimbot, скрой меню через RightShift и удерживай ПКМ. Состояние доступно через UI Settings → Show aim status или status watermark: ожидание клавиши, ввод текста, выбранный игрок или причины исключения целей — team, wall, FOV, distance, body part. Если все игроки находятся в одной Roblox Team, выключи Skip teammates; если цель вне круга, увеличь FOV radius.

Исправлена обработка ПКМ, которую игра помечает как обработанную. В Hold проверяется текущее состояние клавиши, включая пропущенные события нажатия и отпускания. Камера обновляется после обычных контроллеров; Scriptable-камера по умолчанию допускается. Опции полного запрета наведения при открытом меню и на Scriptable-камере доступны, но изначально выключены.

### Профили

Укажи имя на вкладке UI Settings и нажми **Save profile**. Файлы сохраняются в файловой области executor: `Legit/Universal/configs/<имя>.json`. Сохраняются настройки функций, клавиши, RGB и прозрачность цветов, акцент и масштаб UI. Старые профили версии 1 совместимы: отсутствующие новые настройки сохраняют текущие значения. **Load profile** загружает выбранное имя; автоматической загрузки при старте нет.

Для имени разрешены латинские буквы, цифры, пробел, `_` и `-`, до 48 символов. Reset defaults возвращает исходные настройки, включая выключенные ESP и Aimbot. Активное удержание / Toggle при загрузке профиля сбрасывается.

### Silent Aim

**Aimbot → Silent Aim → Enable silent aim**. Экипируй огнестрельное оружие, закрой меню и стреляй обычным способом. Camera Aim можно оставить выключенным. Silent Aim не вращает камеру, не нажимает стрельбу и не создаёт фиктивные результаты попаданий. Его фильтры, FOV и выбор цели независимы от Camera Aim. По умолчанию исключены лежачие и ForceField, включена проверка стен и пауза при открытом меню.

Настраиваются часть тела, приоритет Screen / Distance / Lowest health, Hit chance per ray, FOV, максимальная дистанция, цвет / прозрачность круга, команда / друзья / лежачие / ForceField, HP и prediction. Вероятность применяется к каждому подходящему Raycast, а не к гарантированно распознанному выстрелу: у дробовиков и FastCast несколько лучей могут иметь разные решения. Длина исходного луча сохраняется, меняется только направление. Серверные ограничения дальности и регистрации урона продолжают действовать.

Поддерживаются лучи из скриптов экипированного инструмента и конкретных модулей `ReplicatedStorage.NewModules.Shared.Services.RayHandler` / `FastCastRedux`. Для общих модулей требуется Exclude-фильтр с локальным персонажем / инструментом. Начало луча должно быть в пределах 12 studs от локального HumanoidRootPart; должен наблюдаться ввод стрельбы или Tool.Activated. Оружие распознаётся по `Values.SERVER_Ammo` / `Ammo` / `StoredAmmo`, melee-инструменты исключаются. Неизвестные пути gun-модулей и другие схемы ammo пока требуют адаптации.

Silent и Melee используют один dispatcher. Внутри него нет вызовов методов Roblox; цель и видимость подготавливаются вне hook до 30 раз в секунду. Нужны те же executor API, что и Melee. Сам по себе существующий Raycast hook не подтверждает серверное попадание. Прямые вызовы `workspace.Raycast(...)` не перехватываются.

**Show silent status** показывает текущий статус. Для логов используй **UI Settings → Start silent capture**, затем включи функцию и воспроизведи выстрел. В отчёте есть `SilentStatus`, `Silent.ray.seen`, `Silent.ray.redirected` и причины пропуска: нет цели / не стреляет / неподходящий caller / shared filter / дальний origin / hit chance. Проверены локальные заглушки, а работа с реальными выстрелами в текущей игре требует подтверждения.

**Show silent shot traces** включён по умолчанию. Голубая линия показывает перенаправленный Raycast до его клиентского попадания или конца луча; оранжевая — локальный gun-луч, оставленный без изменения, с причиной `PASS: no target`, `not firing`, `hit chance` и т. п. Маркер `client hit` использует позицию результата настоящего Raycast, `ray end` означает отсутствие точки попадания. Серый **Show original ray direction** — исходный вектор без дополнительной проверки столкновений. Золотой **Show silent target guide** показывает выбранную точку наведения и подписан `SA target (guide)`; это не траектория и не подтверждение попадания. Когда цели нет, отображается текущий статус Silent.

Можно менять время жизни и толщину линий. Записываются только лучи, прошедшие ограничения локального gun-origin / caller / фильтра, поэтому чужие лучи и неизвестные источники не выдаются за твои выстрелы. Отсутствие цели в FOV не мешает показывать подходящий исходный gun-луч. Неподходящие origin / caller остаются в счётчиках отладки. Короткие сегменты FastCast могут выглядеть как короткие отрезки; не подменяются искусственной длинной линией до цели. Данные выбираются до 20 раз в секунду, очередь и число видимых трасс ограничены 16, GUI создаётся / обновляется только вне hook. По истечении времени, при сбросе / смене оружия и выгрузке отображение очищается. Трассировка не меняет алгоритм hit chance, длину луча или результат игрового Raycast.

### Melee Aura для Criminality

Экспериментальный модуль: совместимость с текущей Criminality и конкретным executor в живой игре не проверена. Включи **Combat → Enable melee aura**, экипируй melee-инструмент и закрой меню. По умолчанию дальность — 10 studs до выбранной части тела, интервал активации — 0.5 s, окно перенаправления лучей после удара — 0.35 s. Выключи **Auto attack**, чтобы бить вручную с перенаправлением лучей. **Show melee status** показывает выбранную цель, паузу, отсутствие оружия или недоступность hook API.

Распознаётся полный найденный перечень из [категории Melees Criminality Wiki](https://criminality.fandom.com/wiki/Category:Melees), включая событийные и старые варианты. Реестр из 35 названий доступен в `MeleeAura.WeaponNames` в `src/MeleeAura.lua`; дополнительно учтены короткие имена Slayer, Military Machete и отдельные названия скинов. Пробелы, регистр, дефисы и апострофы не влияют на распознавание: Golf Club / Golfclub и Metal Bat / Metal-Bat эквивалентны. Неизвестное имя допускается только при наличии структуры `Melee` (ModuleScript), `AnimsFolder` (Folder) и `WeaponHandle` (BasePart), наблюдавшейся у Criminality melee-инструмента. Все эти проверки выполняются вне hook. Наличие имени или структуры не подтверждает серверную регистрацию урона каждым событийным оружием.

Для UpperTorso у R6 используется Torso. Цель выбирается вокруг персонажа на 360°, без экранного FOV. Фильтры Melee независимы от Aim и ESP. Ввод текста, работа с контролами меню, потеря фокуса и смерть персонажа приостанавливают функцию.

Распознаются также семейства Fists, ZombieFists, InfectedFists, X-Fist / XFists с необязательным числовым суффиксом: например, `__ZombieFists1`, `__ZombieFists2`, `__ZombieFists123`. Подчёркивания и регистр не влияют на проверку; совпадения по подстроке вроде ZombieFistsLauncher не допускаются. Silent Aim тоже использует это распознавание и исключает такие кулаки из gun-режима.

**Combat → Skip downed / ragdolled** включён по умолчанию и сохраняется в профиле. Лежачий игрок исключается из целей по `ReplicatedStorage.CharStats.<Username>.Downed` (BoolValue); дополнительно учитываются BoolValue / атрибут `Downed` на персонаже и Humanoid, PlatformStand и состояния Humanoid Ragdoll / FallingDown. Расположение CharStats.Down­ed сверено с [публичным исходником для Criminality](https://github.com/Trojankill/Criminality/blob/main/CriminalityV2.lua); отдельная проверка текущей игры ещё нужна. Малое HP само по себе не считается состоянием Downed. Ссылки на BoolValue готовятся вне hook, поэтому их сменившийся `Value` может немедленно остановить перенаправление луча без вызовов методов Roblox. При отсутствии цели автоактивация не выполняется. Это фильтр выбора целей; он не отменяет обычные игровые попадания по другим персонажам при широком взмахе оружия.

Нужны `hookmetamethod`, `getnamecallmethod`, `checkcaller`, `getcallingscript`; `newcclosure` используется при наличии. Hook устанавливается при первом включении и обрабатывает только `workspace:Raycast` из скрипта экипированного инструмента либо модуля с `RaycastHitbox` в имени, во время окна удара. Начало луча должно находиться рядом с персонажем, а длина входящего луча не должна превышать Reach + 6 studs. Прямые вызовы `workspace.Raycast(...)`, другие hitbox API и переименованные общие модули не перехватываются.

При включении показывается уведомление с именами отсутствующих API. Этот статус имеет приоритет над паузой из-за открытого меню, чтобы несовместимость executor не выглядела как обычное ожидание.

Подготовка целей, проверка ввода и видимости выполняются вне hook, не чаще 30 раз в секунду. Внутри `__namecall` нет вложенных методов Roblox: они могли подменять активное имя метода, вызывая ошибки вроде `GetFocusedTextBox is not a valid member of Workspace`. Дальность, здоровье и смена персонажа проверяются по свойствам непосредственно при луче; стены, ForceField и прочие фильтры обновляются при следующей подготовке. Подробные строки о лучах ограничены по частоте ещё до построения путей объектов. Выключенная Aura пропускает вызовы без упаковки аргументов и расчёта перенаправления.

При обновлении старый dispatcher остаётся с пустым Owner, а исправленный устанавливается один раз. После большого потока ошибок рекомендуется переподключиться к серверу перед проверкой новой версии, чтобы начать с чистой консоли и окружения executor. Остановка потока ошибок сама по себе не подтверждает регистрацию melee-урона.

Перенаправляется направление настоящего Raycast; его параметры фильтрации и результат сохраняет движок Roblox. При этом луч может удлиниться до цели. Auto attack вызывает `Tool:Activate()`: игровые cooldown, анимации, проверки дистанции и серверная регистрация попаданий продолжают действовать. Увеличение Reach не гарантирует попадание. При выключении и выгрузке обработчик пропускает все вызовы; один общий dispatcher повторно используется при перезапуске, без накопления hooks и без перезаписи hooks других скриптов.

При исследовании просмотрен [публичный пример Criminality](https://github.com/Trojankill/Criminality/blob/main/CriminalityV2.lua): там Melee Aura основана на remote-вызовах. Здесь реализован отдельный Raycast-подход, без загрузки и выполнения стороннего скрипта или копирования его remote-протокола.

## Проверка

Проверки используют Luau CLI и заглушки Roblox. Для Obsidian используется отдельная заглушка API: тестируется подключение настоящего адаптера к методам библиотеки, без утверждения о визуальном рендеринге. Параметр `--compiler` дополнительно компилирует все 13 рабочих Lua-файлов, включая настоящие исходники Obsidian / Lucide и `Legit.lua`:

```shell
python tests/run.py --luau /path/to/luau --compiler /path/to/luau-compile
```

Проверены семь вкладок, callbacks контролов, привязки мыши / клавиатуры, профили и совместимость старых настроек, цвета / прозрачность, drag / key capture guards, фильтры целей, R6, FOV, стены, prediction, ESP и очистка. Через настоящий render callback проверены наведение при пропущенном InputBegan, обработанный игрой ПКМ, открытое меню, Scriptable-камера, отпускание клавиши без InputEnded, блокировка при вводе текста и причины отсутствия цели.

Отдельно проверен однострочник из README: один HTTP-запрос, запуск без Drawing и getcustomasset, отсутствие загрузки зависимостей и повторный запуск.

Для Melee Aura проверены границы hook, сохранение аргументов и результата Raycast, фильтры целей, смерть и выход из дальности между кадрами, интервал автоатаки, ручные удары и истечение окна, пауза, профили, очистка соединений, повторное использование hook и отсутствие нужных API. Эти проверки используют заглушки и не подтверждают серверную регистрацию урона.

Также проверены восстановление свойств и респавн, режимы прыжка, освещение и удаление собственных эффектов, поиск / приоритеты игроков в Aim и Melee, возврат камеры, профили новых функций, server actions и ленивый запуск внешних инструментов с обработкой ошибок. Для launcher-тестов используются инертные Lua-ответы; настоящие Dex и SimpleSpy не выполняются. Их опубликованные файлы отдельно скачаны и скомпилированы без запуска.

Для диагностики проверены кольцевой буфер, ограничение частоты, экспорт, актуализация API executor, причины паузы, счётчики melee, изоляция ошибок getcallingscript и сохранение результатов / ошибок исходного игрового метода.

Дополнительно 14 ноября 2026 года новая сборка была запущена через Xeno v1.3.65 в живом клиенте Criminality: наблюдался интерфейс Obsidian, проверены отказ preflight при отсутствующих API и создание читаемого отчёта `Legit/Universal/logs/latest.txt`. Автоатака в этой проверке была выключена. Серверная регистрация melee-урона и полноценные игровые сценарии не подтверждены. Пользовательские персонажи, собственные системы команд / здоровья и другие скрипты камеры могут требовать адаптации. Персонажи, не загруженные на клиент из-за StreamingEnabled, недоступны для ESP и наведения.

## Исходники

- `Legit.lua` — автономный файл для однострочного запуска; сборка: `python tools/build_bundle.py`.
- `main.lua` — исходник приложения, настройки и профили.
- `src/ObsidianUI.lua` — адаптер контролов Obsidian, профилей и блокировки ввода во время работы с меню.
- `vendor/Obsidian/` — закреплённая версия Obsidian и Lucide с MIT-лицензиями.
- `src/NativeUI.lua` — сохранённый предыдущий интерфейс; не используется и не включается в сборку.
- `src/Engine.lua` — ESP, выбор целей, управление камерой и очистка.
- `src/MeleeAura.lua` — Melee Aura, фильтры целей, автоактивация оружия и Raycast hook.
- `src/SilentAim.lua` — независимый выбор цели, FOV, ограничение gun-лучей и подключение к общему hook.
- `src/UniversalTools.lua` — персонаж, освещение, восстановление свойств, список игроков, наблюдение и внешние launchers.
- `src/Diagnostics.lua` — ограниченный журнал в памяти, отчёты и ручной экспорт в workspace executor.
- `src/GuiDrawing.lua` — стандартные Roblox GUI-примитивы для ESP/FOV.
- `vendor/Tokyo.lua`, `assets/` — сохранённые исходники предыдущей версии; приложение их не использует.
- `tests/` — проверки без запуска Roblox.

Происхождение библиотеки и список исправлений: [THIRD_PARTY.md](THIRD_PARTY.md).
