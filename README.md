# Legit — Obsidian

Интерфейс на [Obsidian](https://github.com/deividcomsono/Obsidian) с восемью вкладками из референсов: **Aimbot, Combat, Character, ESP, World, Misc, Players, UI Settings**. Настройки Aim, ESP и Melee Aura сохранены и сгруппированы по назначению. UI поддерживает цвета, прозрачность, привязки клавиш и масштаб. Левая панель вкладок сужена до 170 px вместо 276 px при окне 920 px; названия вкладок остаются видимыми.

## Запуск

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/sinmirka/Legit/main/Legit.lua"))()
```

Один файл, одна HTTP-загрузка. Obsidian, Lucide и логика встроены в `Legit.lua`; дополнительных загрузок Lua при запуске нет. Drawing API и `getcustomasset` не нужны. Иконки и текстуры используют Roblox asset IDs.

Нужны `loadstring`, `getgenv` и файловые функции для профилей. ESP, Aimbot, Silent Aim, Melee и все изменения персонажа / освещения изначально выключены. Старый экземпляр при повторном запуске выгружается. Кнопки Dex и Remote Spy загружают внешние инструменты отдельно, только по нажатию.

В Aimbot по умолчанию проверка команды и исключение ForceField отключены: цели выбираются среди остальных живых игроков. Эти фильтры можно включить отдельно. У Melee собственные фильтры; ForceField изначально исключается.

## Управление

| Действие | По умолчанию |
| --- | --- |
| Открыть / закрыть меню | **RightShift** |
| Наведение | **Удерживать ПКМ**, после включения Enable aimbot |
| Изменить клавишу наведения | Aimbot → Aim key, затем нажать нужную клавишу / кнопку мыши |
| Очистить привязку | Выбрать Aim key и нажать **Backspace** |
| Изменить клавишу меню / масштаб | UI Settings → Menu key / UI scale |
| Выгрузить UI и функции Legit | **END** или UI Settings → Unload |

Наведение работает при открытом меню, когда курсор находится вне панели. Клик по настройкам, ввод текста и перетаскивание приостанавливают наведение. Можно отдельно включить Pause while menu is open.

Ползунки меняются перетаскиванием; цвет и прозрачность задаются в color picker Obsidian. **UI Settings → Show aim status** показывает состояние наведения; **Toggle status watermark** включает строку состояния.

### Отладочные логи

В **UI Settings → Debugging / Combat diagnostics** нажми **Start melee capture** или **Start silent capture**. Это включает только сбор диагностики, без включения атак. Затем включи нужную функцию, закрой меню и воспроизведи проблему. **Save debug report** сохраняет `Legit/Universal/logs/latest.txt` в файловой workspace executor, **Copy debug report** копирует отчёт. **Stop debug capture** останавливает запись с сохранением накопленного отчёта, **Clear debug log** очищает его и счётчики.

Журнал хранит последние 400 записей в памяти. В нём доступны API executor, текущие настройки, причина паузы, распознанное оружие, причины исключения целей, попытки Activate / события Activated, количество наблюдаемых и перенаправленных Raycast и причины пропуска лучей. С подробной трассировкой записываются путь вызывающего скрипта и клиентский результат луча. Частые записи ограничены по частоте. Счётчики исключения целей считают оценки на Heartbeat, а не уникальных игроков.

По умолчанию логирование и вывод в консоль выключены. Ничего автоматически не отправляется в сеть и не пишется в файлы. Ошибки диагностики hook пропускают вызов исходному методу; ошибки и возвращаемые значения самой игры сохраняются. Клиентское попадание не доказывает серверный урон. Без событий Raycast в отчёте нельзя заключать, что игра вообще не использует Raycast: прямые `.Raycast(...)` вызовы этим hook не видны.

Для проверки окружения без полной загрузки UI есть `tools/probe_runtime.lua`: он сохраняет `Legit-runtime-probe.txt` в workspace executor, без установки hooks и вызовов игровых remotes. В живой проверке Xeno 14 ноября 2026 года `hookmetamethod` и `getnamecallmethod` оказались `nil`; текущая Raycast Aura требует эти API и в таком окружении недоступна.

### Что отложено

По референсам сохранены вкладки и близкие группы настроек. Отложены Triggerbot, recoil / wallbang / auto-block, отдельные Rage Melee / Hit Reg, Ghost Hunt, no fall / ragdoll, удаление игровых препятствий, infection ESP, auto pickup / lockpick / staff detector и hitsounds. Fly и анимационные инструменты тоже отложены до отдельной реализации и проверки в игре.

### Универсальные функции

Настройки персонажа применяются к текущему Humanoid и подхватывают респавн. Noclip запоминает исходный CanCollide каждой части. При выключении или выгрузке изменённые значения восстанавливаются, если ими всё ещё управляет Legit; более новые изменения игры не перезаписываются. Эти клиентские настройки не обходят серверные ограничения движения.

**Character → Spinbot** вращает персонажа вокруг вертикальной оси. Spin speed задаётся в градусах в секунду; отрицательное значение меняет направление, ноль останавливает вращение. Look up angle наклоняет голову вверх через Motor6D шеи, сохраняя смещение сустава. Положение персонажа и настройки камеры не меняются; можно продолжать смотреть от третьего лица. Поддержаны стандартные R6/R15. Во время сидения, ragdoll и при закреплённом корне функция приостанавливается. AutoRotate и исходная поза шеи восстанавливаются при выключении, респавне и выгрузке. Поворот тела останавливается на текущем направлении. Отображение позы у других клиентов и серверные ограничения требуют проверки в игре.

**Character → Limit jump rate** включает задержку между фактическими прыжками; Delay between jumps задаёт её от 0.1 до 3 s (по умолчанию 0.5 s). Первый прыжок доступен сразу. После перехода Humanoid в Jumping повторный вход в это состояние блокируется до конца задержки, в том числе после быстрого приземления. При выключении, смерти, респавне или выгрузке восстанавливается исходная доступность прыжков. Игровое отключение Jumping не отменяется. Высота прыжков и прыжки в воздухе не меняются. Обе новые функции изначально выключены и сохраняются в профиле.

World меняет локальное освещение. Bloom и ColorCorrection создают собственные эффекты и удаляют только их. Для Atmosphere используется имеющийся объект с восстановлением свойств, либо создаётся временный объект. Прозрачность цветов относится к ESP/FOV; у свойств Lighting нет opacity.

В Players **Friend** исключает игрока из Aim, Silent и Melee, сохраняя его в ESP. **Enemy** предпочитается среди целей, прошедших фильтры; Sticky у Camera Aim продолжает удерживать текущую допустимую цель. Приоритеты действуют до выхода игрока / выгрузки, в профиль не сохраняются. Наблюдение отслеживает респавн выбранного игрока и возвращает камеру при остановке, его выходе или выгрузке.

Dex / SimpleSpy запускаются как отдельные инструменты и закрываются через собственные интерфейсы. Они могут загружать свои зависимости и требовать дополнительные API executor. Legit обрабатывает ошибку загрузки / компиляции / запуска и допускает повторную попытку; повторное успешное нажатие в одном экземпляре Legit не запускает вторую копию. Их работа в клиенте здесь не проверялась.

### Цвета и прозрачность

- **Opacity**: `0` — невидимо, `1` — непрозрачно.
- Итоговая видимость Chams учитывает Global opacity, Fill opacity и прозрачность выбранного цвета. Fade и Pulse дополнительно изменяют её.
- Приоритет цвета персонажа от высшего к низшему: **HP ESP → друзья → текущая цель → rainbow → цвет команды → видимый / скрытый → базовый цвет**. Выключи переопределения, если хочешь видеть базовые Fill / Outline.
- Для независимого цвета рамки выключи **Match character color**. Прозрачность текста и его обводки регулируются отдельно.
- **Character outline** — силуэт Highlight со стандартной толщиной Roblox. Настраиваемая толщина относится к 2D-рамкам, скелету, линиям и FOV.

### HP ESP и состояние

В **ESP → HP ESP colors** включается цвет заливки и контура по HP: 0–15 — Low health (красный по умолчанию), далее плавный переход до Full health (зелёный) при MaxHealth. Этот режим имеет приоритет над другими цветами Highlight. **Labels → Downed / Ragdolled status** показывает отдельную цветную подпись: лежачий с HP ≤15 — красный `Downed`, с HP >15 — оранжевый `Ragdolled`. У обычного персонажа подписи нет, даже при низком HP. Учитываются CharStats, BoolValue / атрибуты Downed / Ragdolled / Ragdoll, PlatformStand и состояния Humanoid. Для подписи нужны включённые ESP и Labels; для заливки — Chams.

### Выбор цели

FOV — радиус в пикселях вокруг центра экрана. Deadzone останавливает поворот камеры, когда цель достаточно близко к центру; выбранная цель при этом сохраняется. Большая Aim speed означает более быстрое наведение. Instant убирает плавность.

Для R6 выбор UpperTorso / LowerTorso использует Torso, а UpperArm / UpperLeg — соответствующие Arm / Leg. Другие отсутствующие части тела исключают цель. Смещение XYZ задаётся в мировых координатах; prediction добавляет скорость HumanoidRootPart × Prediction time. Наведение поворачивает камеру; стрельба и регистрация попаданий остаются механиками игры.

Check walls проверяет путь до выбранной части тела. ESP проверяет видимость до головы; для Highlight дополнительно применяется режим Occluded. Для 2D-элементов проверка головы определяет отображение всего оверлея. Прозрачное стекло с CanQuery может считаться препятствием; вода игнорируется.

### Если нет наведения

Включи Aimbot → Enable aimbot, скрой меню через RightShift и удерживай ПКМ. Состояние доступно через UI Settings → Show aim status или status watermark: ожидание клавиши, ввод текста, выбранный игрок или причины исключения целей — team, wall, FOV, distance, body part. Если все игроки находятся в одной Roblox Team, выключи Skip teammates; если цель вне круга, увеличь FOV radius.

Исправлена обработка ПКМ, которую игра помечает как обработанную. В Hold проверяется текущее состояние клавиши, включая пропущенные события нажатия и отпускания. Камера обновляется после обычных контроллеров; Scriptable-камера по умолчанию допускается. Опции полного запрета наведения при открытом меню и на Scriptable-камере доступны, но изначально выключены.

### Профили

Укажи имя на вкладке UI Settings и нажми **Save profile**. Файлы сохраняются в файловой области executor: `Legit/Universal/configs/<имя>.json`. Сохраняются настройки функций, клавиши, RGB и прозрачность цветов, акцент и масштаб UI. Старые профили версии 1 совместимы: отсутствующие новые настройки сохраняют текущие значения. **Load profile** загружает выбранное имя; автоматической загрузки при старте нет.

Для имени разрешены латинские буквы, цифры, пробел, `_` и `-`, до 48 символов. Reset defaults возвращает исходные настройки, включая выключенные ESP и Aimbot. Активное удержание / Toggle при загрузке профиля сбрасывается.

### Silent Aim

**360 silent aim** — отдельный переключатель, по умолчанию выключен. Включённый режим выбирает цели вокруг персонажа, включая находящихся за камерой и за краями экрана, независимо от радиуса FOV. Работает с Criminality, Universal Raycast и Auto fire. Приоритет Screen в этом режиме использует расстояние до персонажа; Lowest health продолжает выбирать по HP. Максимальная дальность, стены, друзья / команда, HP, ForceField и лежачие фильтруются как прежде. Круг FOV скрывается; обычный Camera Aim не меняется. Настройка сохраняется в профиле. Угол выстрела всё ещё может ограничиваться сервером игры; работа в живой игре не проверена.

**Cycle targets (360 auto fire)** при включённых 360 и Auto fire обходит допустимые цели от ближайшей к дальней, затем начинает новый круг. Каждая успешная активация ввода переводит очередь к следующей цели; смена идёт по интервалу Auto fire, а не каждый кадр. Успешная активация ввода не подтверждает фактический выстрел или урон: игровые cooldown и патроны продолжают действовать. Ошибка ввода не двигает очередь. Умершие, вышедшие и отфильтрованные цели пропускаются. Этот режим использует расстояние вместо обычного приоритета, поддерживает оба адаптера Silent Aim, изначально выключен и сохраняется в профиле.

**Universal Raycast (any weapon)** по умолчанию выключен: используется адаптер Criminality с проверкой оружия. При включении работают игровые `workspace:Raycast(origin, direction, params)` без проверки Tool, названия оружия, ammo values и модулей Criminality. Можно использовать неизвестное оружие или оружие без Roblox Tool. Нужны включённый Enable silent aim и API `hookmetamethod`, `getnamecallmethod`, `checkcaller`, `getcallingscript`. Переключатель сохраняется в профиле.

Универсальный режим сохраняет FOV, фильтры, hit chance и 3D-трассеры. Меняется только направление, исходная длина и параметры фильтрации луча сохраняются. Обрабатываются лучи с началом рядом с локальным персонажем либо камерой; это общий перехват и он может затронуть другие игровые Raycast рядом с ними. Попадание вычисляет исходный Raycast. Прямые вызовы `workspace.Raycast(...)`, старые FindPartOnRay, серверные лучи и другие системы стрельбы не поддерживаются этим режимом. Наличие Raycast в игре само по себе не гарантирует совместимость или регистрацию урона сервером. При выключении возвращаются проверки Criminality.

**Aimbot → Silent Aim → Enable silent aim**. Экипируй огнестрельное оружие, закрой меню и стреляй обычным способом. Camera Aim можно оставить выключенным. Silent Aim не вращает камеру и не создаёт фиктивные результаты попаданий. Его фильтры, FOV и выбор цели независимы от Camera Aim. По умолчанию исключены лежачие с HP ≤15 и ForceField, включена проверка стен и пауза при открытом меню.

**Auto fire on target** — отдельный переключатель, изначально выключен. При включённых Silent Aim и Auto fire скрипт активирует стрельбу по выбранной допустимой цели: в FOV либо вокруг персонажа при включённом 360. Используются фильтры Silent Aim: команда / друзья, стены, HP, лежачие, ForceField и дальность. При потере цели, фокуса, вводе текста и работе с UI стрельба приостанавливается; опция Pause with menu также учитывается. При Hit chance = 0 автовыстрелов нет.

**Auto fire interval** задаёт интервал попыток, по умолчанию 0.15 s. **Auto fire input**: Auto использует экипированный Tool, иначе `mouse1click`; Tool вызывает штатный `Tool:Activate()` и отпускает через `Deactivate()` на следующем обновлении; Mouse кликает ЛКМ через API executor, в том числе для оружия без Tool. Если игра слушает собственный ввод вместо Tool, выбери Mouse. Отсутствующий API / ошибка активации показываются в Show silent status и диагностике. Выключение, пауза и выгрузка отпускают активированный скриптом Tool. Настройки сохраняются в профиле. Автовыстрел работает в обоих режимах; игровые cooldown, патроны и серверная регистрация сохраняются. В живом Potassium эта функция ещё не проверена.

Настраиваются часть тела, приоритет Screen / Distance / Lowest health, Hit chance per projectile, FOV, максимальная дистанция, цвет / прозрачность круга, команда / друзья / лежачие / ForceField, HP и prediction. Решение принимается один раз при создании пули; у дробовика — отдельно для каждой дробинки. Сохраняются скорость и максимальная дальность. Направление и вектор скорости согласованы; для переданного FastCast ускорения рассчитывается короткая баллистическая дуга. Недостижимая при этой скорости цель пропускается. Серверные ограничения регистрации урона продолжают действовать.

Адаптер перехватывает конкретный dispatcher `ReplicatedStorage.NewModules.Client.Services.Effects`. Только вызов `Shoot` с локальным флагом и ссылкой на текущее экипированное оружие может изменить список направлений. В выгруженном `Gun` этот же объект списка используется и для клиентского эффекта, и для штатной отправки выстрела серверу. Ссылка на список, origin и остальные аргументы сохраняются. Дополнительных сетевых вызовов скрипт не делает. Для баллистики читаются `Velocity` и `Acceleration` из `Config.BulletSettings`; изменённые игрой конфигурации ещё требуют живой проверки. Оружие распознаётся по ammo values, melee-инструменты исключаются.

`Fire`, `FireWithBlacklist`, `FireWithWhitelist` конкретного `ReplicatedStorage.NewModules.Shared.Services.FastCastRedux` связываются с подготовленным списком по shot ID и направлению. Такой запуск повторно не меняется. Если записи Effects нет, для `Fire` / `FireWithBlacklist` есть запасной перехват запуска: нужны локальный флаг и текущий персонаж в аргументе shooter / blacklist. Направление и вектор скорости меняются согласованно один раз, перед симуляцией. Чужие выстрелы и неподтверждённый whitelist пропускаются. Запасной путь меняет клиентский запуск; совпадение с серверным направлением и регистрация урона требуют проверки в игре. Короткие сегменты `workspace:Raycast` не меняются.

Нужны `hookfunction` и `checkcaller`; `getcallingscript` необязателен. Цель и видимость подготавливаются вне hook до 30 раз в секунду. Отсутствие Effects больше не блокирует запасной FastCast-путь. **Show silent status** и `SilentBackend` в диагностике показывают `Gun directions`, `FastCast launch fallback` или ожидание первого выстрела. Счётчик `Silent.projectile.fallback` помогает определить используемый путь. Совместимость с Potassium и серверный урон здесь не проверены.

**3D shot traces** включён по умолчанию. Beam в мире соединяет начало выстрела с последней точкой реальных `LengthChanged` / `RayHit` конкретной пули. Голубой означает перенаправленный запуск, оранжевый — неизменённый. Шар появляется только при клиентском сигнале попадания; он не подтверждает серверный урон. Без событий FastCast линия не выдумывается. Это прямая от начала до конца, а не вся баллистическая кривая. Ширина задаётся в studs, время затухания — в секундах после последнего события.

Серый **Show original ray direction** — дополнительный 3D-ориентир исходного направления без проверки столкновений. Золотой **Show silent target guide** — экранная подсказка выбранной цели. Оба изначально выключены. Пул ограничен 16 лучами и 16 caster с двумя соединениями на каждый. Части закреплены, не участвуют в столкновениях, касаниях и raycast. При выключении / смене оружия лучи скрываются и наблюдатели отключаются; при выгрузке 3D-объекты удаляются. Установленные hooks после выгрузки пропускают исходные вызовы.

### Melee Aura для Criminality

Экспериментальный модуль: совместимость с текущей Criminality и конкретным executor в живой игре не проверена. Включи **Combat → Enable melee aura**, экипируй melee-инструмент и закрой меню. По умолчанию дальность — 10 studs до выбранной части тела, интервал активации — 0.5 s, окно перенаправления лучей после удара — 0.35 s. Выключи **Auto attack**, чтобы бить вручную с перенаправлением лучей. **Show melee status** показывает выбранную цель, паузу, отсутствие оружия или недоступность hook API.

Распознаётся полный найденный перечень из [категории Melees Criminality Wiki](https://criminality.fandom.com/wiki/Category:Melees), включая событийные и старые варианты. Реестр из 35 названий доступен в `MeleeAura.WeaponNames` в `src/MeleeAura.lua`; дополнительно учтены короткие имена Slayer, Military Machete и отдельные названия скинов. Пробелы, регистр, дефисы и апострофы не влияют на распознавание: Golf Club / Golfclub и Metal Bat / Metal-Bat эквивалентны. Неизвестное имя допускается только при наличии структуры `Melee` (ModuleScript), `AnimsFolder` (Folder) и `WeaponHandle` (BasePart), наблюдавшейся у Criminality melee-инструмента. Все эти проверки выполняются вне hook. Наличие имени или структуры не подтверждает серверную регистрацию урона каждым событийным оружием.

Для UpperTorso у R6 используется Torso. Цель выбирается вокруг персонажа на 360°, без экранного FOV. Фильтры Melee независимы от Aim и ESP. Ввод текста, работа с контролами меню, потеря фокуса и смерть персонажа приостанавливают функцию.

Распознаются также семейства Fists, ZombieFists, InfectedFists, X-Fist / XFists с необязательным числовым суффиксом: например, `__ZombieFists1`, `__ZombieFists2`, `__ZombieFists123`. Подчёркивания и регистр не влияют на проверку; совпадения по подстроке вроде ZombieFistsLauncher не допускаются. Silent Aim тоже использует это распознавание и исключает такие кулаки из gun-режима.

**Combat → Skip downed at 15 HP or below** включён по умолчанию и сохраняется в профиле. Лежачие с HP >15 допускаются; при HP ≤15 игрок исключается из целей по `ReplicatedStorage.CharStats.<Username>.Downed` (BoolValue); дополнительно учитываются BoolValue / атрибут `Downed` на персонаже и Humanoid, PlatformStand и состояния Humanoid Ragdoll / FallingDown. Расположение CharStats.Down­ed сверено с [публичным исходником для Criminality](https://github.com/Trojankill/Criminality/blob/main/CriminalityV2.lua); отдельная проверка текущей игры ещё нужна. Малое HP само по себе не считается состоянием Downed. Ссылки на BoolValue готовятся вне hook, поэтому их сменившийся `Value` может немедленно остановить перенаправление луча без вызовов методов Roblox. При отсутствии цели автоактивация не выполняется. Это фильтр выбора целей; он не отменяет обычные игровые попадания по другим персонажам при широком взмахе оружия.

Нужны `hookmetamethod`, `getnamecallmethod`, `checkcaller`, `getcallingscript`; `newcclosure` используется при наличии. Hook устанавливается при первом включении и обрабатывает только `workspace:Raycast` из скрипта экипированного инструмента либо модуля с `RaycastHitbox` в имени, во время окна удара. Начало луча должно находиться рядом с персонажем, а длина входящего луча не должна превышать Reach + 6 studs. Прямые вызовы `workspace.Raycast(...)`, другие hitbox API и переименованные общие модули не перехватываются.

При включении показывается уведомление с именами отсутствующих API. Этот статус имеет приоритет над паузой из-за открытого меню, чтобы несовместимость executor не выглядела как обычное ожидание.

Подготовка целей, проверка ввода и видимости выполняются вне hook, не чаще 30 раз в секунду. Внутри `__namecall` нет вложенных методов Roblox: они могли подменять активное имя метода, вызывая ошибки вроде `GetFocusedTextBox is not a valid member of Workspace`. Дальность, здоровье и смена персонажа проверяются по свойствам непосредственно при луче; стены, ForceField и прочие фильтры обновляются при следующей подготовке. Подробные строки о лучах ограничены по частоте ещё до построения путей объектов. Выключенная Aura пропускает вызовы без упаковки аргументов и расчёта перенаправления.

При обновлении старый dispatcher остаётся с пустым Owner, а исправленный устанавливается один раз. После большого потока ошибок рекомендуется переподключиться к серверу перед проверкой новой версии, чтобы начать с чистой консоли и окружения executor. Остановка потока ошибок сама по себе не подтверждает регистрацию melee-урона.

Перенаправляется направление настоящего Raycast; его параметры фильтрации и результат сохраняет движок Roblox. При этом луч может удлиниться до цели. Auto attack вызывает `Tool:Activate()`: игровые cooldown, анимации, проверки дистанции и серверная регистрация попаданий продолжают действовать. Увеличение Reach не гарантирует попадание. При выключении и выгрузке обработчик пропускает все вызовы; один общий dispatcher повторно используется при перезапуске, без накопления hooks и без перезаписи hooks других скриптов.

При исследовании просмотрен [публичный пример Criminality](https://github.com/Trojankill/Criminality/blob/main/CriminalityV2.lua): там Melee Aura основана на remote-вызовах. Здесь реализован отдельный Raycast-подход, без загрузки и выполнения стороннего скрипта или копирования его remote-протокола.

## Проверка

Проверки используют Luau CLI и заглушки Roblox. Для Obsidian используются заглушки API: проверяются адаптер, ширина панели, масштаб и клавиши меню. Параметр `--compiler` дополнительно компилирует все 14 рабочих Lua-файлов, включая настоящие Obsidian, Lucide и `Legit.lua`. Внешний вид новой сборки в живом клиенте не проверялся:

```shell
python tests/run.py --luau /path/to/luau --compiler /path/to/luau-compile
```

Проверены восемь вкладок, callbacks контролов, привязки мыши / клавиатуры, профили и совместимость старых настроек, цвета / прозрачность, drag / key capture guards, фильтры целей, R6, FOV, стены, prediction, ESP и очистка. Через настоящий render callback проверены наведение при пропущенном InputBegan, обработанный игрой ПКМ, открытое меню, Scriptable-камера, отпускание клавиши без InputEnded, блокировка при вводе текста и причины отсутствия цели.

Отдельно проверен однострочник из README: один HTTP-запрос, запуск без Drawing и getcustomasset, отсутствие загрузки зависимостей и повторный запуск.

Для Melee Aura проверены границы hook, сохранение аргументов и результата Raycast, фильтры целей, смерть и выход из дальности между кадрами, интервал автоатаки, ручные удары и истечение окна, пауза, профили, очистка соединений, повторное использование hook и отсутствие нужных API. Эти проверки используют заглушки и не подтверждают серверную регистрацию урона.

Также проверены восстановление свойств и респавн, режимы прыжка, освещение и удаление собственных эффектов, поиск / приоритеты игроков в Aim и Melee, возврат камеры, профили новых функций, server actions и ленивый запуск внешних инструментов с обработкой ошибок. Для launcher-тестов используются инертные Lua-ответы; настоящие Dex и SimpleSpy не выполняются. Их опубликованные файлы отдельно скачаны и скомпилированы без запуска.

Для диагностики проверены кольцевой буфер, ограничение частоты, экспорт, актуализация API executor, причины паузы, счётчики melee, изоляция ошибок getcallingscript и сохранение результатов / ошибок исходного игрового метода.

Дополнительно 14 ноября 2026 года новая сборка была запущена через Xeno v1.3.65 в живом клиенте Criminality: наблюдался предыдущий интерфейс Obsidian, проверены отказ preflight при отсутствующих API и создание читаемого отчёта `Legit/Universal/logs/latest.txt`. Автоатака в этой проверке была выключена. Серверная регистрация melee-урона и полноценные игровые сценарии не подтверждены. Пользовательские персонажи, собственные системы команд / здоровья и другие скрипты камеры могут требовать адаптации. Персонажи, не загруженные на клиент из-за StreamingEnabled, недоступны для ESP и наведения.

Melee Aura всегда исключает друзей Roblox и игроков с приоритетом **Players → Friend**, включая старые профили с `SkipFriends=false`. Пока проверка дружбы не завершена успешно, игрок также защищён. Автоатака продолжает работать по остальным допустимым целям, даже если друг находится рядом. Случайное попадание широким взмахом по другу не блокируется. Приоритет / дружба повторно проверяются перед перенаправлением луча. Уже начатые игровые анимации и ручные удары этим фильтром не отменяются.

### Infinite stamina

**Character → Criminality / Stamina → Infinite stamina** (по умолчанию выключен, сохраняется в профиле). Основано на поиске GC-таблиц с полем `S` из [публичного скрипта Criminality](https://github.com/Trojankill/Criminality/blob/main/CriminalityV2.lua). Кандидаты ограничены изменяемыми таблицами с числом `S` в диапазоне 0–100. Эти значения удерживаются на 100, без вызовов игровых remotes. Это эвристика: поле `S` не доказывает принадлежность стамине, работа текущей игры ещё требует проверки.

Нужен `getgc`. Сканирование выполняется при включении / смене персонажа, затем раз в 15 секунд; если ничего не найдено или сканирование завершилось ошибкой — раз в 5 секунд. Между сканированиями обновляется только кеш (не более 128 таблиц). **Rescan stamina** обновляет кеш вручную, **Show stamina status** показывает недоступный API / отсутствие кандидатов / число пополняемых таблиц. Отладочный отчёт содержит `StaminaStatus`, `StaminaTables`, `InfiniteStamina`. Выключение и выгрузка прекращают пополнение и освобождают ссылки; текущее количество стамины не откатывается к старому значению.

### Instant interaction

**Misc → Instant interaction (E)** убирает удержание кнопки у обычных `ProximityPrompt`: `HoldDuration` устанавливается в 0. Нажимать E / экранную кнопку нужно самостоятельно. Дальность, Enabled и проверка видимости не меняются; автоподбор и вызовы `fireproximityprompt` отсутствуют. На старте включения выполняется один обход workspace, затем учитываются новые / показанные prompts через события. Полного обхода дерева каждый кадр нет. При выключении / выгрузке возвращается последняя известная длительность игры, если значение всё ещё принадлежит скрипту. Настройка сохраняется в профиле.

Подход найден в [CriminalityV2.lua](https://github.com/Trojankill/Criminality/blob/main/CriminalityV2.lua) и сверен с [документацией ProximityPrompt](https://create.roblox.com/docs/reference/engine/classes/ProximityPrompt). Проверены локальные сценарии существующих / новых prompts, изменения длительности игрой, профилей и выгрузки. Работа на конкретных деньгах / контейнерах в текущей Criminality ещё не проверена: собственная система взаимодействий, мини-игра или серверный таймер могут требовать другой реализации.

Ссылки на изученные исходники и зависимости собраны в [SOURCES.md](SOURCES.md).

Переход на Iris: используется SirMallard/Iris, закреплённый на `1043909bccf0c532811d60f915a1ce1ec28db867`. Логика исходников в `vendor/Iris/lib` не изменена (нормализованы пробелы в концах строк); локальный загрузчик собирается `tools/build_iris.py`. Весь Iris встроен в `Legit.lua`, поэтому отдельной HTTP-загрузки модулей, демо или шрифтов нет. Старые UI-адаптеры не загружаются. Вкладки и игровые настройки сохранены; World остаётся отдельно.

### ESP объектов Criminality

**ESP → Values / Criminality objects**: Scrap, Green crate (зелёный), Red crate (красный), Airdrop (жёлтый), Dealer (фиолетовый). Каждый тип включается отдельно от player ESP. Есть расстояние, максимальное число ближайших объектов, подписи, дистанции, Highlight, видимость сквозь стены и **Refresh object ESP**.

Scrap ищется в `SpawnedPiles` и по названию; дилеры — по dealer / armory / LegalStore / IllegalStore и известным папкам из публичного примера. Кейсы распознаются по названиям / строковым атрибутам CrateType / Type, затем по цвету деталей внутри объекта crate. Это адаптеры структуры, а не подтверждение текущих названий на сервере. Неопределённые кейсы без признаков типа пропускаются.

Один обход карты при включении; далее очередь новых объектов (64 за обновление), кеш до 2048 объектов и отображение до выбранного лимита ближайших (по умолчанию 128). Удалённые объекты и выключенные эффекты очищаются. Локальные проверки покрывают цвета, дубликаты частей, streaming, дальность, лимит и выгрузку. Требуется проверка распознавания на живой карте.

### Velocity speed

**Character → Speed options → Velocity speed** (по умолчанию выключено). Используется подход из публичного CriminalityV2: горизонтальная скорость HumanoidRootPart задаётся по MoveDirection, вертикальная AssemblyLinearVelocity.Y сохраняется. Нет изменения CFrame или вызовов remotes. Сидение, PlatformStand и Anchored приостанавливают запись; без ввода скорость не навязывается. Выключение прекращает записи без возврата устаревшей физической скорости. Настройка сохраняется в профиле, статус попадает в диагностику.

Обычный Humanoid.WalkSpeed, Noclip, Infinite Jump и Override Jump удалены из UI и выполнения. Поля этих функций в старых профилях игнорируются. Наличие метода в публичном скрипте не гарантирует отсутствие обнаружения / серверной коррекции. Проверены локальные векторы, Y, отсутствие ввода, сидение, выключение и невозможность запуска удалённых методов через старые поля; живое подтверждение ещё требуется.

### Obsidian: управление и проверка

Окно перемещается и изменяет размер средствами Obsidian. **RightShift** показывает / скрывает меню, **END** выгружает приложение. Нажми на поле назначения клавиши, затем клавишу или кнопку мыши; Backspace очищает назначение. Цвет и прозрачность меняются в color picker; правый клик по ползунку позволяет вводить значение.

Адаптер Obsidian использует штатный `SetSidebarWidth(170)`, чтобы панель вкладок, разделитель и область настроек меняли размеры согласованно. Масштаб применяется через `SetDPIScale`.

RightShift обрабатывается независимо от `gameProcessedEvent` и закрывает меню даже при фокусе на поле ввода Obsidian. Для печатных клавиш ввод текста защищён, назначение клавиш имеет приоритет. Курсор освобождается штатным `UnlockMouseWhileOpen` Obsidian через `GuiButton.Modal`.
